Where every eMAX field comes from

When a customer pays for an RHP warranty on the microsite, it is posted to eMAX as a Cash Sale and a payment receipt. Each table below lists a field eMAX receives, where its value comes from, and an example.

The example throughout is warranty RHP-20261105-E94325329: 4 tyres, paid RM 108.00 including 8% SST.

Payment recorded→Customer check→Cash Sale(returns CS no.)→Payment receipt(returns OR no.)

Posting runs once, right after payment. If it fails, an alert email is sent and nothing is retried automatically. Check eMAX first, then retry with POST api/emax/post/{warrantyId}.

Cash Sale

POST{EmaxWebAPIUrl}/Sales?Method=ImportSales

A JSON array with one sales header. Nothing is sent if any of these settings is blank: EmaxBranchCode, EmaxCustomerCode, EmaxItemCode_{plan} (or EmaxItemCode), EmaxPaymentType, EmaxPaymentAccountCode.

Cash Sale PDF

GET{EmaxWebAPIUrl}/AppWA/Sales/GetSalesPdf

Called when someone clicks Cash Sale on the Status page. It is a GET with a JSON body. eMAX returns a print link, and the microsite downloads the PDF and shows it.

FieldSourceExample

Bearer token claims

The microsite builds this token itself (signed HS256, then encrypted A256KW / A256CBC-HS512). It is valid for one hour and never reaches the browser.
